Living Desktop 1.x

Update policy

Last updated: 15 November 2026

Distribution

Commercial updates are distributed only as publisher-approved Windows packages. A release is not considered public merely because a local or QA installer exists.

Signing

Public installers and shipped executables must carry the approved Windows code-signing identity. Users should not be instructed to ignore an unexpected publisher or signature warning.

Versioning

Living Desktop uses semantic versioning for public releases: major versions may contain incompatible product or entitlement changes; minor versions contain backward-compatible features or workflow improvements; patch versions contain fixes, compatibility changes, security corrections and polish.

Version 1.0 behavior

Version 1.0 does not rely on a background network updater. Updates may be delivered manually through the approved merchant/storefront or publisher download channel.

Data preservation

An in-place update must preserve compatible application state and must not move or delete original user files. Installer and uninstaller flows must respect protected recovery state and refuse destructive removal when recovery cannot be safely completed.

Security and critical fixes

The publisher may issue an expedited update for a security or data-safety defect. Critical fixes should identify affected versions and the recommended action.

Rollback and clean-install testing

Rollback is not guaranteed across incompatible major versions. Before public release, install, update, uninstall and recovery behavior are tested in a clean Windows environment.
