Privacy policy

Last updated: 15 November 2026

Living Desktop is local-first. Version 1.0 does not require an online account and does not implement advertising, analytics, telemetry, or background upload of user files.

Data processed on your device

Living Desktop may process file and folder paths you explicitly add as references; folders you explicitly choose for Today; Smart Space, Scene, Quick Shelf, Post-it and Fence layout state; local Windows system status used by optional system views; and Windows Shell metadata used to show icons or open or reveal selected files.

Original files

The V1 reference-based Fence does not move original files or Windows desktop icons when you add, rearrange or remove Living Desktop references.

Storage

Application state is stored locally in the Windows application-data area for Living Desktop. The product does not hold a server-side copy of that local workspace state.

Network and telemetry

Version 1.0 contains no application telemetry, analytics SDK, advertising SDK, remote account service or product data-upload service. Living Desktop does not transmit file contents, paths, notes, system metrics or usage history to the publisher.

Opening a file, folder, File Explorer or another installed application may cause Windows or that application to perform its own network activity. That activity is outside Living Desktop's control.

Permissions and user choice

Today reads only folders you explicitly choose. Folder Portal reads only a folder already referenced by you. Optional Windows system views are local and read-only.

Retention and deletion

Local application state remains until you remove it, reset application data, or uninstall according to the supported uninstall process. No server-side copy of that state is retained by Living Desktop.

Website hosting

This informational site is hosted on GitHub Pages and contains no first-party analytics or advertising scripts. GitHub may process technical connection information under its own privacy statement.

Changes

Material privacy changes will be documented with the corresponding product update. A future feature that introduces online processing must update this policy before that feature is released.
